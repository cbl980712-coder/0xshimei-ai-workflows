# 设计网站筛选器

收藏了上百个设计网站，真要做页面时不知道先开哪几个？这个工具读你的收藏清单（链接 + 简介），合并重复、按用途归类、把信息不足的标「待补」，再按你的项目类型和眼下卡点推荐最多 3 个，并说明各自解决什么问题。**只从你自己的收藏里挑。**

不需要登录、不需要付费 API、不需要装任何 Python 包。

## 先下载（从 GitHub 拿到工具）
**兼容性（先看这句）：网页版用 Chrome 打开，其他浏览器未验证。命令行需要 Python，已验证版本为 3.9。**

GitHub 的 Download ZIP 解压后只有一层文件夹，名字是「仓库名-分支名」（下面写成 `<仓库名>-main`，以你实际看到的为准）。本 README、提示词、脚本、网页版都直接在这一层里，**下面所有文件和命令都以这一层为准**，不用再往里找：
```
<仓库名>-main/                 ← 解压出来的这一层，命令都在这里运行
├── README.md  SKILL.md  prompts.md      ← 说明、Claude Code 入口、提示词
├── 设计站筛选器.html                     ← 网页版，双击打开
├── pick_sites.py  md_to_csv.py  build_index.py  build_html.py  run_examples.sh   ← 脚本
├── rules.json                           ← 可改的关键词表
├── 设计参考索引.html                     ← 索引页样例（例子 3 生成）
├── templates/                           ← 示例清单.csv、设计网站导入模板.csv 等
└── examples/                            ← 三组真实例子（01、02、03）
```
1. 打开仓库首页，点绿色的 **Code** → **Download ZIP**，下载后解压。
2. 进入解压出来的 `<仓库名>-main` 文件夹（里面直接就能看到 `README.md`、`设计站筛选器.html` 和 `templates/`）。
3. 用 Chrome 打开：双击 `设计站筛选器.html`（不用装任何东西；其他浏览器没验证过）。
4. 页面里点「选择文件」，选 `templates/示例清单.csv`（路径相对 HTML 所在的这一层；点「用示例清单」也行）；项目类型选「落地页」；眼下卡点填「配色老是不协调」；点「筛选」。**应看到 Colors & Fonts、Blend 和 Colorffy** 这三个站。
   - 没出现这三个站？先核对：① 导入的是不是 `templates/示例清单.csv`（换成自己的清单，推荐当然不同）；② 项目类型是不是「落地页」；③ 卡点是不是填了「配色老是不协调」（配色这个词要在里面）。

## 三步上手

### 1. 装什么
- 想用命令行版：需要 Python，已验证版本为 3.9（其他版本没测过）。
  - Mac：打开「终端」，输入 `python3 --version`；没有的话 `xcode-select --install` 或到 python.org 下载。
  - Windows：到 python.org 下载安装，安装时勾选 "Add python to PATH"；之后用 `python`（或 `py`）代替下面的 `python3`。
- 不想装任何东西：用 Chrome 双击 `设计站筛选器.html`，不联网、数据不上传（但没有联网核对链接的功能）。
- 想让 Claude Code 带你做：把解压出来的整个文件夹复制到你项目的 `.claude/skills/design-site-picker/`（`SKILL.md` 要和 `pick_sites.py`、`rules.json` 放在同一层，只拷 `SKILL.md` 跑不起来）。也可以不装，只用 `prompts.md` 里的提示词。

**先确认环境好了**，在解压出来的这一层（和 `pick_sites.py` 同级）打开终端，跑这一条，应当看到「推荐结果」和 3 个站：
```
python3 pick_sites.py templates/示例清单.csv --type 落地页 --stuck "配色老是不协调" --out test_out
```
（跑完可以删掉 `test_out/`。）然后看 `examples/` 里三组真实例子的输入和输出。

### 2. 把你的收藏放进去
做成 CSV（Excel/Numbers 另存为 CSV，选 UTF-8），照 `templates/设计网站导入模板.csv`：

| 名称 | 网址 | 简介 | 分类 |
|---|---|---|---|
| Typ.io | https://typ.io | 看真实网站用了什么字体、怎么搭配 | Typography |

- 只有「网址」是必须的；中英文表头都认（name/url/description/category）。
- **简介写得越具体，推荐越准**：写"免费配色库，几千组手选配色，可按色相筛选"比空着强。**简介少于 12 个字（含空格和标点）会被标「待补」、不参与推荐**，所以"免费配色库"这种太短的也会进待补；把它写长一点再跑一次，推荐就会变（待补清单里每个站都写了原因）。
- 手上是 markdown 清单（`- [名称](网址) 简介`，GitHub 上的 awesome 清单就是这种）：`python3 md_to_csv.py 清单.md 清单.csv`。

### 3. 怎么跑
```
python3 pick_sites.py 你的清单.csv --type 落地页 --stuck "首屏配色老是不协调" --out result --check
```
- `--type`：落地页 / 产品界面 / 运营图（在 `rules.json` 的 `project_types` 里可以加）。
- `--stuck`：眼下卡点，一句话。能识别配色、字体、排版、灵感、组件、图标、素材、样机、原型、动效、无障碍、品牌、学习这些词（见 `rules.json` 的 `stuck_words`）。
- `--check`：联网打开推荐站做一次粗核对（可选，没网就去掉）。它不是「打不开就一律换掉」，按情况分开处理：
  - **换掉**：HTTP 404、500 这类错误，连不上或超时，或者能打开但去掉脚本和样式后正文不到 300 字（纯 JS 渲染的页面可能误中）。换掉的站不再出现在推荐里，但会列在 `推荐.md` 的「被换掉的站」和 `result.json` 的 `skipped` 里，附原因和网址，原站你还能自己点开看；换掉后会从清单里补下一个站再核对。
  - **保留并标记**：返回 401、403、429、503。收到这些状态时，脚本不能确认页面是否可用（可能是要登录、被限流、服务暂时不可用，也可能是对方不让脚本访问，脚本不判断是哪种），所以保留链接，`推荐.md` 的「联网核对」一行写「请你在浏览器里点开确认」。
  - **保留并标记（单列）**：返回的是 Cloudflare 人机验证页（无论状态码是 200 还是 403）。「联网核对」一行会写明是 Cloudflare 验证页，同样请你手动打开；脚本不替网站判断原因。
  - **保留并标记**：跳转到了别的域名（比如站点已迁移）。仍然留在推荐里，「联网核对」一行写「已跳转到 …」，由你判断是不是想要的站。
  - **保留**：能正常打开、正文够长。「联网核对」一行写 HTTP 状态、正文字数和页面里命中的相关词。
- `--top`：最多 3（上限就是 3）。
- 没填 `--stuck` 或项目类型不在 `rules.json` 里时，会在屏幕上提示，只按默认用途推荐，结果会比较泛。

**出错时**：文件找不到、空文件、不是 CSV、编码不对、缺「网址」列，都会用一句中文告诉你怎么改，不会甩 Python 报错。分号或 Tab 分隔，两个版本都认。编码分开说：命令行版会尝试读取 GBK（国内旧版 Excel 另存的 CSV 也能读，会提示建议改存 UTF-8）；网页版只读 UTF-8，导入时如果文件解码失败，会提示「这个文件不是有效的 UTF-8 CSV，请另存为 CSV UTF-8 后重新导入」，这时表头没问题，不用去改表头。只有文件解码成功、却确实没有「网址」列时，才会显示「找不到网址列」并列出读到的表头。

## 输出在哪
`--out` 指定的目录里：
- `推荐.md`：最多 3 个站，每个写适合解决什么、依据你清单里哪句简介；
- `清单整理.csv`：合并后的全部站，带用途标签和「可用/待补」；
- `待补清单.csv`：信息不足的站，最后一列留给你补；
- `素材清单.csv`：推荐站 × 要找什么，「授权已核对」留给你填；
- `result.json`：同样的内容，给别的程序用。

想把整理后的清单做成可搜索的静态索引页：在解压出来的这一层运行（接上面 `--out result` 的路径）。**索引只收录「清单整理.csv」里标为「可用」的站。可用指简介达到筛选门槛，不表示网址已逐一核对。**标「待补」的站不会出现在索引里、搜不到，它们仍在 `待补清单.csv`（同在 `result/` 里），补好简介重跑 `pick_sites.py` 后才会进索引。
```
python3 build_index.py "result/清单整理.csv" "索引.html"
```
生成后双击 `索引.html` 打开。Windows 把 `python3` 换成 `python`。

另外 `build_html.py`：重新生成单文件 `设计站筛选器.html`（改了 `rules.json` 后用）。

## 想调规则
全在 `rules.json`：每个用途的关键词、卡点说法、项目类型的默认用途权重、「简介少于几个字算待补」。改完重跑即可；要更新浏览器版再跑 `python3 build_html.py`。

## 限制（老实说）
- 只在 Mac + Python 3.9 + Chrome 上测过：网页版用 Chrome，其他浏览器（含 Edge、Safari、Firefox）未验证；命令行已验证 Python 3.9，其他版本和 Windows 写法（`python`/`py`）没实测。
- 超大清单会慢：实测 10 万行约 25 秒（本机，估算你的电脑会不同）。浏览器版没测这么大。
- 单元格里超过 2000 字的简介会被截断。
- 标签是**关键词匹配**，不是理解。简介里一句话带到"字体"就会打上字体标签；"The Stocks"这种综合素材站会同时命中好几个用途。推荐理由只引用你简介里的原文，不替你评价网站质量。
- 联网核对只检查：能不能打开、正文够不够长、页面里有没有相关词，处理方式见上面的 `--check`。401/403/429/503 或 Cloudflare 人机验证页，脚本不能确认页面是否可用，保留并标为「请自己点开确认」，不代表站挂了；纯 JS 渲染的页面文字很少，可能被判为「正文太短」而被换掉，换掉的站在 `推荐.md` 里能看到。网页版不联网，不做这项核对。
- 清单里没有的站不会被推荐；清单里没简介的站（待补）也不会被推荐。示例里 425 个站有 232 个因简介太短被待补，这是真实情况。
- 授权：推荐站的图片、字体、样机能不能商用，要自己到站上核对；`素材清单.csv` 里有一列留给你记。
- 示例清单来自 GitHub 上两份公开的 awesome 清单（2026-11-16 下载），较老，里面有已迁移或失效的链接。示例里的耗时是我这台电脑上的实测墙钟时间（含联网核对），同一台电脑复跑三次是 3.8/7.3/3.3、3.7/6.8/3.5、4.0/7.6/3.8 秒，换网络会不同。
