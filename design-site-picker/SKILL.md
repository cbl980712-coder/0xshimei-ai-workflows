# 设计网站筛选器

只从用户**自己的收藏**里推荐，不凭空推荐新网站。所有命令在本目录（kit/）里运行，只用 Python 3.8+ 标准库。

## 第 1 步：问清两件事
1. 项目类型：落地页 / 产品界面 / 运营图（`rules.json` 里的 `project_types` 可以加）。
2. 眼下卡点：一句话，例如「首屏配色老是不协调」。含糊就追问一次，问「卡在配色、字体、排版、图标、素材还是样机？」

## 第 2 步：把收藏清单变成 CSV
- 已有 CSV：表头含「网址」即可，「名称、简介、分类」可选（中英文表头都认）。
- 只有 markdown 清单（`- [名称](网址) 简介`）：`python3 md_to_csv.py 清单.md 清单.csv`
- 浏览器书签导出的 HTML：先让用户转成 CSV，或用提示词包里的"整理成 CSV"提示词。

## 第 3 步：跑筛选
```
python3 pick_sites.py 清单.csv --type 落地页 --stuck "首屏配色老是不协调" --out result --check
```
脚本做四件事：合并重复链接（忽略 http/https、www、末尾斜杠、utm 参数）→ 按 `rules.json` 的关键词给每个站打用途标签 → 简介少于 12 字、没命中任何用途、或简介写着"还没公开/已停止维护"的标「待补」 → 按卡点和项目类型打分，每个卡点用途至少给一个站，最多 3 个。`--check` 会联网打开推荐站：打不开的换下一个；401/403/429/503 和 Cloudflare 人机验证页都保留并标为"请自己点开确认"（脚本不能确认页面是否可用，不判断原因）；被跳转到别的域名会写出来。

## 第 4 步：检查并交付（Claude 要做的）
读 `result/推荐.md`，逐条核对：
- 每个推荐的"依据"必须是清单里原有的简介原文，不要自己编这个站"很好用"；
- 推荐站的用途和用户卡点对得上，对不上就说明，并换 `清单整理.csv` 里同标签的下一个；
- 把 3 个站的「适合解决什么」用一两句人话写给用户，并标出哪些没能自动核对；
- 告诉用户 `待补清单.csv` 里有多少个、怎么补（填最后一列"这个站解决什么问题"，再把简介回填到原清单重跑）。
不要宣称"已验证站点质量"：脚本只核对了能不能打开、页面有没有相关词。

## 输出
`result/推荐.md`（最多 3 个站 + 理由）、`清单整理.csv`（合并后全部站 + 标签 + 状态）、`待补清单.csv`、`素材清单.csv`（推荐站 × 要找什么，授权列留给用户填）、`result.json`。想不装 Python 也行：双击 `设计站筛选器.html`，规则相同，但不联网核对。
