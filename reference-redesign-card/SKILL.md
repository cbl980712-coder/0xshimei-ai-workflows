# 参考图改版指令卡

解决的问题：参考图找到了，但说不清它哪里好，也说不清自己的页面该改哪儿。
所有命令都在本文件所在目录（kit/）下执行。需要 Node 22+ 和 Chrome 或 Edge，不装任何包、不登录、不调付费 API。

## 输入（缺哪样就问用户，别猜）

1. 我的页面：网址，或截图文件路径
2. 页面目标：一句话（谁来、几秒内要做成什么）
3. 参考页：网址，或截图文件路径
4. 想借鉴什么：留白 / 标题层级 / 按钮样式（可多选，可更具体，例如“首屏大标题”）

## 步骤

### 0. 确认环境
`node scripts/doctor.mjs` 全是 ✅ 才继续。

### 1. 先量再看（一条命令）
先写两个圈选文件（格式见 templates/marks.example.json）：参考页上想借鉴的位置、我页面上猜测对应的位置。
`{"label":"1 标题","selector":"h1"}` 或 `{"label":"2 留白","box":[x,y,宽,高]}`（整页坐标）。
一开始不知道选择器就先不传圈，跑一次看 `对比.md` 里的标题/按钮表（里面有每个元素的选择器），再补圈重跑。

```
node scripts/run.mjs --own <我的网址> --ref <参考网址> --out work/01 --own-marks 我的圈.json --ref-marks 参考圈.json
```
产出：`ref-marked-top.png`、`mine-marked-top.png`（带编号红圈）、`对比.md`（量出来的字号、间距、按钮样式并排）。
哪一侧是图片，哪一侧就没有量测数据、圈选只能用 `box`，该侧每个数字都要写“目测”：
- 参考是图片、我的能打开：我的页照常量，`finish.mjs` 能完整验收；不会生成 `对比.md`，读 `mine.json` 和截图。
- 我的页只有图片：不能套 CSS、没有改后实测值。`checklist.json` 的 `own_url` 写截图路径，`checks` 不写，`finish.mjs` 会跳过验收，只出 `改版清单.md` 和 `指令卡.html`；`css` 只是文字建议，要如实告诉用户没验证过，也不要承诺有 `mine-after-top.png`。

### 2. 读证据，不凭感觉
- 用 Read 工具看两张 `*-marked-top.png`，再读 `对比.md`。
- 每个借鉴点写成一对：参考页哪里（带数字）↔ 我页面哪里（带数字、带选择器）。
- 先问“参考页这样做对页面目标有什么用”，再决定借不借。参考页有、但与目标无关的写进 not_borrow。
- 参考页的元素在我这里不存在时（例如我没有大按钮），写清“最小改法（只改样式）”和“彻底改法（要改 HTML）”，验收只量最小改法。

### 3. 写 checklist.json（模板 templates/checklist.template.json）
硬规矩：
- `keep` 至少 2 条，写“哪里不动 + 为什么”。没有这一栏就是在乱改。
- `items` 不超过 6 条，按 P0 / P1 / P2 排：P0 = 直接影响页面目标的（主按钮、首屏一句话），P1 = 层级与留白，P2 = 打磨。
- 每条必须有 `where`（选择器 + 页面上的字）、`change`（具体数值，不写“适当加大”）、`how_to_check`（人看什么 + 量什么）。
- `checks` 的阈值来自**参考页量出来的数字或明确的目标**（例如按钮高 ≥ 参考页的 64px），不是看着改后结果倒推。
- `checks.prop` 可用任意 computed style（fontSize、borderRadius、backgroundColor…）或 rect.width / rect.height / rect.top / rect.bottom；op 用 >= <= == != between。
- 选择器必须在我的页面上真能选中，写完以后由第 5 步验证。

### 4. 写 patch.css（和 checklist 里每条的 css 一致）
这是在浏览器里临时套上去预览的样式，不会改线上网站。
常见坑（真实遇到过）：站点原规则优先级更高，裸选择器压不过。办法：照原规则的选择器写，或加 `#id` 前缀、`[class]`。
不要覆盖用来居中的左右外边距；改了底色记得连里面的文字颜色一起改。

### 5. 验收 + 出成品（一条命令）
```
node scripts/finish.mjs work/01
```
会做三件事（只重新打开我的页面，不碰参考页）：改前、改后各开一个全新浏览器量一遍每条 checks（只检查清单里配置过的数值项）；写 `改后验收清单.md`；生成 `改版清单.md` 和 `指令卡.html`。
- 有 ❌：回到 3/4 改 patch 或阈值。如果是 patch 写错就改 patch；如果阈值本身不合理，改阈值时要在 change 里写清为什么。
- 全 ✅ 后，**必须再看一眼 `mine-after-top.png`**：数字通过不等于好看（例如居中被改坏、文字变得看不见，只有看图才发现）。发现新问题就补一条 check。

### 6. 交付给用户
给：`指令卡.html`、`改版清单.md`、`改后验收清单.md`、`patch.css`。
说明哪些是量出来的、哪些是判断；改版是在浏览器里临时预览，线上没改。
