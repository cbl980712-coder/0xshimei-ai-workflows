# step-card-tutorial：录屏 → 关键帧 → 图文教程卡

本技能目录里有三样东西，都在这个 SKILL.md 旁边：
- `video_step_splitter.py`：切帧 + 排版脚本（只依赖 Python 3.8+、Pillow、numpy；输入是视频时还需要 ffmpeg）
- `step_card_template.html`：卡片模板（想换样式改它，不用改脚本）
- 本文件：你（Claude）要做的每一步

下面 `<kit>` 指本技能所在目录，`<work>` 指本次任务的工作目录（自己建一个，别写进 kit/）。

## 第 0 步：确认输入
- 输入是一个视频文件（mp4/mov/webm），或一个文件夹，里面是按文件名排序的连续操作截图（png/jpg）。
- 问用户（若没说）：①软件叫什么、这段操作要完成什么任务；②教程用中文还是英文（默认中文）。
- 检查环境：`python3 -c "import PIL, numpy"`；视频输入再 `ffmpeg -version`。缺什么，告诉用户装什么，不要装全局软件。

## 第 1 步：切关键帧（脚本做，几秒）
```
python3 <kit>/video_step_splitter.py extract <输入视频或截图文件夹> -o <work>
```
脚本会：按 5 帧/秒抽帧 → 在 320×180 的灰度图上比较"当前画面"与"上一张关键帧" → 忽略鼠标指针大小的小色块（指针移动、光标闪烁、单个字符）→ 画面真的变了（弹窗、翻页、开关、选中、输入完成）并稳定下来后，取稳定后的第一帧 → 输出：
- `<work>/frames/step_00.jpg`（起点画面）、`step_01.jpg` …（每个操作之后的画面）
- `<work>/contact_sheet.jpg`（所有关键帧拼成一张总览，带编号和时间）
- `<work>/candidates.json`（每帧时间、变化强度、变化区域 `changed_box_pct`）
- `<work>/steps.draft.json`（空白步骤骨架）

读终端输出：找到几步？默认保留 4~6 步（`--min-steps` / `--max-steps` 可改）。

## 第 2 步：看图，核对步骤数量
用 Read 工具打开 `contact_sheet.jpg`，必要时再逐张打开 `frames/step_XX.jpg`，核对：
- 有没有**漏步**（相邻两张画面差别很大、中间明显少了一个动作）→ 降低灵敏度门槛重跑：`--threshold 0.0006`，或加 `--pixel-diff 10`（淡色高亮也算变化）。
- 有没有**多步/重复**（同一动作拆成两张，如打字到一半）→ 加大 `--merge-gap 3`，或升高 `--threshold`，或在 steps.json 里直接删掉那一步。
- 进度条、动画中途被当成一步 → 把 `--settle 3` 调大。
- 输入是截图文件夹时每张图都视为"已稳定"，只做去重。
重跑直到步骤数合理（常见教程 4~6 步；超过 6 步让用户决定拆成两篇还是合并）。

## 第 3 步：解析鼠标行为与界面变动，写「动作名称 + 详细说明」
对每一张 `step_NN.jpg`，对照上一张（`step_00` 起），回答三个问题：
1. **用户做了什么动作？**（点了哪个按钮/菜单/开关，输入了什么，选了什么）——看鼠标指针停在哪、指针旁有没有点击圈。
2. **界面因此变成了什么？**（弹出什么窗口、哪行高亮、哪个开关变色、出现什么提示）。
3. **读者怎么在自己的屏幕上找到它？**（位置：右上角/左侧菜单/弹窗右下角；颜色；原文按钮上的字，保留软件界面原文）。

然后写进 `<work>/steps.json`（复制 `steps.draft.json` 来改），格式：
```json
{
  "title": "教程标题（说清软件 + 任务）",
  "subtitle": "一句话说明用时/前提",
  "start_image": "frames/step_00.jpg",
  "steps": [
    {"image": "frames/step_01.jpg", "time": "00:03",
     "title": "动作名称：动词开头、不超过 20 字",
     "desc": "详细说明 2~3 句，第一句说怎么操作，第二句说操作后界面变成什么。\n换行 = 新段落。",
     "tip": "可选：易错点/前提，一句话",
     "box": [x, y, 宽, 高],
     "click": [x, y]}
  ]
}
```
写作规则：
- `title` 是**动作**，不是页面名：好 =「点击右上角头像，打开账户菜单」；差 =「账户菜单」。
- `desc` 只写画面里看得见的东西，不猜软件内部逻辑；界面上的按钮/菜单名用原文，加引号「」。
- 不确定的地方（看不清、帧里没出现的结果）宁可写"如果……"或删掉，不要编。
- `box`：红框，单位是**图片宽高的百分比**，`[左, 上, 宽, 高]`；框住"变化的地方"（新弹窗、被选中的行、变色的开关）。`candidates.json` 里的 `changed_box_pct` 是脚本算出的候选框，对的就抄，整屏变化（弹窗压暗背景）时是 null，需要你按图估一个。不需要框就删掉这个字段。
- `click`：红圈中心点 `[x, y]`，也是百分比；只在"这一帧里能看到要点击的位置"时填（例如截图里能看到鼠标刚点的保存按钮）。不确定就不填。
- 每步写完自问：只看这张图 + 这段字，一个没用过这软件的人能照做吗？不能就补位置词。

## 第 4 步：套模板出 HTML
```
python3 <kit>/video_step_splitter.py render <work>/steps.json -o <work>/tutorial.html
```
- 想要单个可以直接发给别人的文件：加 `--embed`（图片转 base64 内嵌）。
- 英文教程：加 `--lang en`。不要起点画面：加 `--no-start`。
- 样式不满意：复制 `step_card_template.html` 改 CSS，用 `--template 你的模板.html` 指定。模板里 `<!--CARD_START-->…<!--CARD_END-->` 之间是单张卡片，占位符见文件。

## 第 5 步：自检并交付
- 用 Read 打开 `tutorial.html` 的前 40 行，确认没有残留 `{{…}}` 占位符（脚本已替换，但换模板时可能漏）。
- 对照 `contact_sheet.jpg` 再看一遍：卡片顺序 = 视频顺序；每张图下的文字和图能对上；红框没有框错地方。
- 给用户：HTML 路径、步骤数、你不确定的地方（例如"第 3 步我无法确认保存是否成功，录屏里没出现提示"）。
- 不要把用户的录屏上传到任何在线服务；全程都在本机。

## 常见问题
| 现象 | 处理 |
|---|---|
| 只找到 1~2 步 | 画面变化很小（只有一行字变了）→ `--threshold 0.0005 --pixel-diff 10` |
| 步骤太多 | 加大 `--threshold`，或 `--max-steps 6` 只留变化最大的 |
| 录屏没有鼠标指针 | 照常切帧；第 3 步只能依据界面变化写，`click` 一律不填 |
| 录屏有大面积动画/视频播放 | 先剪掉那段，或用截图文件夹作输入 |
| 截图文件夹里有重复图 | 脚本会自动去掉和上一张几乎一样的 |
