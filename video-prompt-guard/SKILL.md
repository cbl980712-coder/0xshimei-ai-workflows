# video-prompt-guard

目标：把「盲目抽卡」改成「出片前先过一遍风控」。脚本只用 Python 3 标准库，不联网、不调用任何付费 API。

## 步骤

1. **收集分镜**。让用户给出每个镜头的描述。若用户只给了一段故事，先按「一镜一个动作、≤5 秒」拆成镜头，写成下面的格式存为 `shots.md`：
   ```
   镜头1：描述……
   首帧：（可选）
   尾帧：（可选）
   时长：4秒（可选）
   ```
2. **跑检测**：`python3 -I prompt_guard_checker.py shots.md -o out/`（`--price` 可改单次生成价，默认 4 元）。
3. **读 `out/report.md`**：
   - 风险分 0~1 低，2~4 中，5~8 高，≥9 极高。
   - 「软化后仍高风险」的镜头，**不要直接抽卡**。按清单里的建议拆镜、改写（打斗/拥抱只拍接触前后；文字后期叠；环绕改小幅；>5 秒拆开），把改写结果存成新的 `shots_fixed.md`，回到第 2 步重跑，直到没有「仍高风险」。
4. **显式补首帧、尾帧**：脚本自动起草的首尾帧只是草稿（标了「自动起草，请核对」）。你要为每个镜头写清首帧、尾帧的景别、位置、姿态，并用同一人物参考图生成这两张图。
5. **取 `out/final_prompts.md`** 里每镜头的提示词原样贴入视频平台的「首尾帧」模式；平台没有负向框时，把【负向】改写成正向句放进约束。
6. **试片再出片**：每个镜头先用最短时长/最低档抽 1 条，过了再出高清。
7. **对账**：`python3 -I build_xlsx.py out/ out_fixed/ -o 我的成本表.xlsx --price <单价>` 生成修改前后成本对照（按镜头名对，拆镜新增的单列一行）；用户实际生成后，把真实抽卡次数填回去，校准「参数」页的失败率（默认值是假设，不是实测）。

## 约束

- 不要替用户改剧情；自动软化只改运镜措辞和人群数量。
- 不要宣称节省金额是实测。输出里的抽卡次数是按假设失败率估算的。
- 对用户说明：画面内文字一律后期叠加。
